## [Axiosとは？] (JP)

Axios の正式名称は **Promise ベースの HTTP クライアント** です。  
Web ブラウザ（フロントエンド）からバックエンドサーバー（Node.js / Express など）へ  
HTTP リクエストを送信し、そのレスポンスを処理するために広く利用されているライブラリです。

---

## 1. なぜ Fetch ではなく Axios を使うのか？

ブラウザには標準で `fetch()` API が組み込まれていますが、  
実務では次の理由から Axios が好んで使われます。

### 主なメリット

- **自動 JSON 変換**  
  サーバーからのレスポンスデータを自動的に JavaScript オブジェクトへ変換します。  
  （`fetch` では `response.json()` を手動で呼び出す必要があります）

- **リクエスト／レスポンス・インターセプター（Interceptors）**  
  すべてのリクエストに JWT トークンを自動付与したり、  
  レスポンスエラーを共通ロジックで処理する際に非常に便利です。

- **エラーハンドリングの一貫性**  
  HTTP エラー（401、403、500 など）が発生すると、自動的に `catch` ブロックへ渡されるため、  
  エラー処理をシンプルに保つことができます。

- **ブラウザ互換性**  
  比較的古いブラウザ環境でも安定して動作します。

---

## 2. Axios の主なメソッド

Axios のメソッドは、バックエンドで使用される HTTP メソッドと 1:1 で対応しています。

| メソッド | 役割 | 使用例（バックエンド基準） |
| :-- | :-- | :-- |
| axios.get() | データ取得 | 会員情報取得、投稿一覧取得 |
| axios.post() | データ作成 | 会員登録、ログイン |
| axios.put() | データ更新 | プロフィール更新、投稿内容変更 |
| axios.delete() | データ削除 | 退会処理、投稿削除 |

---

## 3. リクエストの流れ例（ログイン）

1. **ユーザー**  
   ログインボタンをクリック

2. **フロントエンド（Axios）**  
   `/auth/login` エンドポイントへ ID と PW を含めて POST リクエストを送信

3. **バックエンドサーバー**  
   ユーザー情報を検証し、JWT トークンを生成してレスポンス

4. **Axios**  
   サーバーから受け取ったレスポンスデータをフロントエンドコードへ渡す

5. **フロントエンド**  
   JWT トークンを `localStorage` などに保存

---

## 4. あわせて知っておきたい関連知識

### Authorization ヘッダーと JWT

- 認証が必要な API リクエストでは、JWT トークンを HTTP ヘッダーに含めて送信します。
- 一般的な形式は次のとおりです。

  `Authorization: Bearer <JWT_TOKEN>`

- Axios の **Request Interceptor** を利用すると、  
  すべてのリクエストにこのヘッダーを自動で付与できます。

---

### Axios Instance

- `axios.create()` を使うことで、共通設定を持つ Axios インスタンスを作成できます。
- `baseURL`、`timeout`、`headers` などを一元管理できるため、  
  プロジェクト規模が大きくなるほど必須の構成です。

---

### localStorage 使用時の注意点

- `localStorage` に保存されたデータはブラウザに永続的に保持されます。
- XSS 攻撃のリスクがあるため、  
  セキュリティ要件が高いサービスでは **HttpOnly Cookie 方式** の併用も検討すべきです。

---

## 5. まとめ

Axios はフロントエンドからバックエンド API を呼び出す際に  
最も広く使われている **標準的な HTTP 通信ライブラリ** です。

- JWT ベースの認証処理
- 共通エラーハンドリング
- 保守性と拡張性

を考慮すると、実務において非常に強力で安定した選択肢と言えます。

## [Axios란?] (KR)

Axios의 정식 명칭은 **Promise 기반 HTTP 클라이언트**입니다.  
웹 브라우저(프론트엔드)에서 백엔드 서버(Node.js / Express 등)에 HTTP 요청을 보내고,  
그에 대한 응답을 처리하기 위해 널리 사용되는 라이브러리입니다.

---

## 1. 왜 Fetch 대신 Axios를 사용하는가?

브라우저에는 기본적으로 `fetch()` API가 내장되어 있지만,  
실무에서는 다음과 같은 이유로 Axios가 더 많이 사용됩니다.

### 주요 장점

- **자동 JSON 변환**  
  서버에서 응답으로 받은 데이터를 자동으로 JavaScript 객체로 변환합니다.  
  (`fetch`는 `response.json()`을 직접 호출해야 함)

- **요청 / 응답 인터셉터 (Interceptors)**  
  모든 요청에 JWT 토큰을 자동으로 추가하거나,  
  응답 에러를 공통 로직으로 처리하는 데 매우 유용합니다.

- **에러 처리의 일관성**  
  HTTP 에러(401, 403, 500 등)가 발생하면 자동으로 `catch` 영역으로 전달되어  
  에러 처리 로직을 단순하게 유지할 수 있습니다.

- **브라우저 호환성**  
  비교적 오래된 브라우저 환경에서도 안정적으로 동작합니다.

---

## 2. Axios의 주요 메서드

Axios의 메서드는 백엔드에서 사용하는 HTTP 메서드와 1:1로 대응됩니다.

| 메서드 | 역할 | 사용 예시 (백엔드 기준) |
| :-- | :-- | :-- |
| axios.get() | 데이터 조회 | 회원 정보 조회, 게시글 목록 조회 |
| axios.post() | 데이터 생성 | 회원가입, 로그인 |
| axios.put() | 데이터 수정 | 프로필 수정, 게시글 내용 변경 |
| axios.delete() | 데이터 삭제 | 회원 탈퇴, 게시글 삭제 |

---

## 3. 요청 흐름 예시 (로그인)

1. **사용자**  
   로그인 버튼 클릭

2. **프론트엔드 (Axios)**  
   `/auth/login` 엔드포인트로 ID와 PW를 담아 POST 요청 전송

3. **백엔드 서버**  
   사용자 정보를 검증한 뒤 JWT 토큰을 생성하여 응답

4. **Axios**  
   서버로부터 받은 응답 데이터를 프론트엔드 코드에 전달

5. **프론트엔드**  
   JWT 토큰을 `localStorage` 등에 저장

---

## 4. 함께 알아두면 좋은 관련 지식

### Authorization Header와 JWT

- 인증이 필요한 API 요청에서는 JWT 토큰을 HTTP 헤더에 포함시켜 전달합니다.
- 일반적인 형태는 다음과 같습니다.

  `Authorization: Bearer <JWT_TOKEN>`

- Axios의 **Request Interceptor**를 사용하면  
  모든 요청에 이 헤더를 자동으로 추가할 수 있습니다.

---

### Axios Instance

- `axios.create()`를 사용하면 공통 설정을 가진 Axios 인스턴스를 만들 수 있습니다.
- `baseURL`, `timeout`, `headers` 등을 한 번에 관리할 수 있어  
  프로젝트 규모가 커질수록 필수적인 구조입니다.

  ```bash
  const api = axios.create({
    baseURL: '/api',
    timeout: 5000,
  });
  ```

---

### localStorage 사용 시 주의사항

- `localStorage`에 저장된 데이터는 브라우저에 영구적으로 유지됩니다.
- XSS 공격에 노출될 가능성이 있으므로,  
  보안 요구사항이 높은 서비스에서는 **HttpOnly Cookie 방식**도 함께 고려해야 합니다.

---

## 5. 정리

Axios는 프론트엔드에서 백엔드 API를 호출할 때  
가장 널리 사용되는 **표준적인 HTTP 통신 라이브러리**입니다.

- JWT 기반 인증 처리
- 공통 에러 핸들링
- 유지보수성과 확장성

을 고려했을 때, 실무에서 매우 강력하고 안정적인 선택지라고 할 수 있습니다.
