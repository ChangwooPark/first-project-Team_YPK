# [localStorage 概要まとめ]（JP）

localStorage は、ブラウザが提供する **「小さな専用倉庫」** と考えると理解しやすい仕組みです。

通常、Web ページをリロードしたり、ブラウザを終了すると  
JavaScript の変数に保存されたデータはすべて消えてしまいます。

しかし、**localStorage に保存したデータは**  
ブラウザを完全に終了して再起動しても、  
さらには **PC を再起動しても保持され続けます。**

---

## localStorage の特徴

- **半永久的な保存**  
  開発者がコードで明示的に削除するか、  
  ユーザーがブラウザのキャッシュを削除しない限り、データは保持されます。

- **ドメイン単位での分離**  
  `localhost:3000` に保存したデータは `google.com` からは参照できません。  
  セキュリティ上の理由により、同一ドメインのデータのみアクセス可能です。

- **テキスト形式のみ保存可能**  
  保存できるのは **文字列（String）** のみです。  
  オブジェクトや配列を保存する場合は、`JSON.stringify()` で文字列化する必要があります。

- **保存容量**  
  約 5MB 程度で、テキストデータの保存には十分な容量があります。

---

## 主な使い方（JavaScript / TypeScript）

バックエンドから受け取った JWT トークンを扱う際、  
次のようなコードを使用します。

| 機能 | コード | 説明 |
| :-- | :-- | :-- |
| データ保存 | `localStorage.setItem('key', 'value')` | 倉庫にデータを保存（例：トークン保存） |
| データ取得 | `localStorage.getItem('key')` | 倉庫からデータを取得（例：トークン取得） |
| データ削除 | `localStorage.removeItem('key')` | 特定のデータのみ削除（例：ログアウト） |
| 全削除 | `localStorage.clear()` | 倉庫をすべて空にする |

---

## JWT と localStorage の関係

本プロジェクトで想定される利用フローは次のとおりです。

- **ログイン成功**  
  バックエンドから返却された token を  
  `localStorage.setItem('token', token)` で保存

- **ページ遷移**  
  ページを移動しても、トークンはブラウザ内に保持されたまま

- **API リクエスト**  
  Axios が `getItem()` でトークンを取得し、HTTP ヘッダーに付与して送信

- **ログアウト**  
  `localStorage.removeItem('token')` を実行し、認証情報を破棄

---

## 注意点（セキュリティ）

localStorage は JavaScript から簡単にアクセスできるため、  
個人情報やパスワードなどの機密情報を直接保存するのは危険です。

本構成では **JWT トークンのみ** を保存します。  
JWT はサーバー側でのみ検証可能な仕組みを持つため、  
localStorage に保存する方式が一般的に採用されています。

※ より高いセキュリティが必要な場合は  
**HttpOnly Cookie** を使用する方法もあります。

---

## まとめ

- **Axios**：バックエンドと通信するための手段  
- **localStorage**：受け取ったデータ（JWT など）をブラウザに保存する場所

# [localStorage 개념 정리] (KR)

localStorage는 브라우저가 제공하는 **“작은 전용 창고”** 라고 이해하면 가장 쉽습니다.

보통 웹페이지를 새로고침하거나 브라우저를 종료하면  
JavaScript 변수에 저장된 데이터는 모두 사라집니다.

하지만 **localStorage에 저장된 데이터는**  
브라우저를 완전히 종료했다가 다시 실행해도,  
심지어 **컴퓨터를 재부팅해도 그대로 유지됩니다.**

---

## localStorage의 특징

- **반영구적 보관**  
  개발자가 코드로 직접 삭제하거나  
  사용자가 브라우저 캐시를 비우지 않는 한 데이터가 유지됩니다.

- **도메인별 격리**  
  `localhost:3000`에 저장된 데이터는 `google.com`에서 접근할 수 없습니다.  
  보안상의 이유로 동일 도메인 내 데이터만 접근 가능합니다.

- **텍스트 형식 저장**  
  저장 가능한 데이터는 **문자열(String)** 뿐입니다.  
  객체나 배열은 `JSON.stringify()`로 문자열로 변환해야 합니다.

- **용량**  
  약 5MB 정도로, 텍스트 데이터를 저장하기에 충분한 공간입니다.

---

## 주요 사용법 (JavaScript / TypeScript)

백엔드에서 받은 JWT 토큰을 다룰 때 주로 사용되는 메서드는 다음과 같습니다.

| 기능 | 코드 | 설명 |
| :-- | :-- | :-- |
| 데이터 저장 | `localStorage.setItem('key', 'value')` | 창고에 데이터 저장 (예: 토큰 저장) |
| 데이터 조회 | `localStorage.getItem('key')` | 창고에서 데이터 꺼내기 (예: 토큰 조회) |
| 데이터 삭제 | `localStorage.removeItem('key')` | 특정 데이터만 삭제 (예: 로그아웃) |
| 전체 삭제 | `localStorage.clear()` | 창고 전체 비우기 |

---

## JWT와 localStorage의 관계

구현하려는 인증 흐름에서 localStorage는 다음과 같이 사용됩니다.

- **로그인 성공**  
  백엔드에서 받은 token 문자열을  
  `localStorage.setItem('token', token)`으로 저장

- **페이지 이동**  
  사용자가 다른 페이지로 이동해도 토큰은 브라우저에 유지됨

- **API 요청**  
  Axios가 `getItem()`으로 토큰을 꺼내 HTTP 헤더에 담아 전송

- **로그아웃**  
  `localStorage.removeItem('token')`을 실행하여 인증 정보 삭제

---

## 주의사항 (보안)

localStorage는 JavaScript 코드로 쉽게 접근할 수 있기 때문에  
비밀번호나 민감한 개인정보를 직접 저장하는 것은 위험합니다.

본 구조에서는 **JWT 토큰만 저장**하며,  
JWT는 서버에서만 검증 가능하므로  
localStorage 저장 방식이 실무에서 가장 흔히 사용됩니다.

※ 보안 수준이 더 필요한 경우  
**HttpOnly Cookie 방식**을 고려할 수 있습니다.

---

## 정리

- **Axios**: 백엔드와 데이터를 주고받는 통신 수단  
- **localStorage**: 전달받은 데이터(JWT 등)를 브라우저에 보관하는 장소
