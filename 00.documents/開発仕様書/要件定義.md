## 【プロジェクト要件定義書（ドラフト）】（JP）

### 1. プロジェクト概要および目的

| 項目 | 内容 | 
| :--- | :--- |
| **プロジェクト名** | **Task Management App** |
| **目的** | ユーザー間のワークスペースを通じて、業務チケット（Task Ticket）を作成・共有・進捗管理し、効率的なコラボレーション環境を提供する |
| **対象ユーザー** | **社内チームメンバー** |

---
### 2. 主要機能および範囲（Scope）

> 本プロジェクトで実装する主要機能は以下のとおりです。

<br>

**2-1. ユーザーおよび認証管理（User & Auth）**

| ID | 機能管理 | 関連エンティティ | 備考 | 
| :--- | :--- | :--- | :--- |
| **AU-01** | ユーザー登録 | User | アカウント（メールアドレス）とパスワードは必須入力。名前（姓／名）は任意。 | 
| **AU-02** | ログイン | User | JWTベースのトークン認証方式を使用。 | 
| **AU-03** | プロフィール管理 | User | ログイン後に名前の変更が可能。（パスワード変更機能は将来的に拡張予定） | 

<br>

**2-2. ワークスペース管理（Workspace）**

| ID | 機能管理 | 関連エンティティ | 備考 | 
| :--- | :--- | :--- | :--- |
| **WS-01** | ワークスペース作成 | Workspace | 作成者が当該ワークスペースの creatorId となる。 | 
| **WS-02** | メンバー招待および参加 | WorkspaceMember | ワークスペースIDまたはコードを通じてメンバーの参加／招待が可能。 | 
| **WS-03** | ワークスペース一覧取得 | Workspace | ユーザーが所属しているすべてのワークスペース一覧を提供。 |
| **WS-04** | メンバー役割付与 | WorkspaceMember | 作成者（Admin）はメンバーに「Admin」「Member」の役割を付与／変更可能。 |

<br>

**2-3. タスクチケット管理（Ticket）**

| ID | 機能管理 | 関連エンティティ | 備考 | 
| :--- | :--- | :--- | :--- |
| **TK-01** | チケット作成 | Ticket | ワークスペース内でのみ作成可能。タイトル、内容、作成者（creatorId）は必須。 | 
| **TK-02** | チケット詳細取得 | Ticket | ワークスペースメンバーのみ閲覧可能。 | 
| **TK-03** | チケット一覧取得 | Ticket | ステータス別（To Do、In Progress 等）にチケットをグルーピングし、ボード形式で提供。 |
| **TK-04** | チケットステータス変更 | Ticket, TicketStatus | チケットの進行ステータス（ticketStatusId）を変更可能。 |
| **TK-05** | チケット担当者の割り当て／変更 | Ticket, User | チケット担当者（assigneeId）をワークスペースメンバーの中から指定、または解除可能（NULL可）。 |
| **TK-06** | チケット修正／削除 | Ticket | チケット内容、期限、優先度などを修正可能。（削除は管理者権限に制限することを検討） |

---
### 3. 非機能要件（Non-Functional Requirements）

<br>

| 項目 | 内容 | 関連DB制約 | 
| :--- | :--- | :--- |
| **セキュリティ** | パスワードは bcrypt を使用してハッシュ化して保存すること。すべてのAPI通信はHTTPSを前提とする。 | User.password（VARCHAR 255） | 
| **データ整合性** | 同一ユーザーが同一ワークスペースに重複して参加できないこと。 | WorkspaceMember（複合主キー） | 
| **拡張性** | チケットの進行ステータス（TicketStatus）はDBテーブルで管理し、将来的なステータス追加時にコード修正不要で対応可能とする。 | TicketStatus | 
| **パフォーマンス** | ワークスペース単位でのチケット取得時、レスポンス時間は500ms以内であること。 | Ticket.workspaceId に対するインデックスを考慮 |

 ## [프로젝트 요건 정의서 (초안)] (KR)

 ### 1. 프로젝트 개요 및 목표

 | 항목 | 내용 | 
| :--- | :--- |
| **프로젝트명** | **Task Management App** |
| **목표** | 사용자 간 워크스페이스를 통해 업무 티켓(Task Ticket)을 생성, 공유 및 진행 상태를 관리하여 효율적인 협업 환경 제공 |
| **대상 사용자** | **내부 팀원 |

---
### 2. 핵심 기능 및 범위 (Scope)

> 본 프로젝트에서 구현할 핵심 기능은 다음과 같습니다.

<br>

**2-1. 사용자 및 인증 관리 (User & Auth)**

 | ID | 기능 관리 | 관련 엔티티 | 비고 | 
| :--- | :--- | :--- | :--- |
| **AU-01** | 회원 가입 | User | 계정(이메일)과 비밀번호는 필수 입력. 이름(성/이름)은 선택적. | 
| **AU-02** | 로그인 | User | JWT 기반 토큰 인증 방식 사용. | 
| **AU-03** | 프로필 관리 | User | 로그인 후 이름 수정 가능. (비밀번호 변경 기능은 추후 확장) | 

<br>

**2-2. 워크스페이스 관리 (Workspace)**

 | ID | 기능 관리 | 관련 엔티티 | 비고 | 
| :--- | :--- | :--- | :--- |
| **WS-01** | 워크스페이스 생성 | Workspace | 생성자가 해당 워크스페이스의 creatorId가 됨. | 
| **WS-02** | 멤버 초대 및 가입 | WorkspaceMember | 워크스페이스 ID 또는 코드를 통해 멤버 가입/초대 가능. | 
| **WS-03** | 워크스페이스 목록 조회 | Workspace | 사용자가 소속된 모든 워크스페이스 목록 제공. |
| **WS-04** | 멤버 역할 부여 | WorkspaceMember | 생성자(Admin)는 멤버에게 'Admin', 'Member' 역할을 부여/변경 가능. |

<br>

**2-3. 태스크 티켓 관리 (Ticket)**

 | ID | 기능 관리 | 관련 엔티티 | 비고 | 
| :--- | :--- | :--- | :--- |
| **TK-01** | 티켓 생성 | Ticket | 워크스페이스 내부에서만 생성 가능. 제목, 내용, 생성자(creatorId)는 필수. | 
| **TK-02** | 티켓 상세 조회 | Tickent | 워크스페이스 멤버만 조회 가능. | 
| **TK-03** | 티켓 목록 조회 | Ticket | 상태별 (To Do, In Progress 등)로 티켓을 그룹화하여 보드 형태로 제공. |
| **TK-04** | 티켓 상태 변경 | Tickent, TicketStatus | 티켓의 진행 상태(ticketStatusId)를 변경 가능. |
| **TK-05** | 티켓 담당자 배정/변경 | Ticket, User | 티켓 담당자(assigneeId)를 워크스페이스 멤버 중 한 명으로 지정하거나 해제 가능 (NULLABLE). |
| **TK-06** | 티켓 수정/삭제 | Ticket | 티켓 내용, 마감일, 우선순위 등을 수정 가능. (삭제는 관리자 권한으로 제한 고려) |


---
### 3. 비기능 요건 (Non-Functional Requirements)

<br>

 | 항목 | 내용 | 관련 DB 제약| 
| :--- | :--- | :--- |
| **보안** | 비밀번호는 bcrypt를 사용하여 해시 저장해야 함. 모든 API 통신은 HTTPS를 가정. | User.password (VARCHAR 255) | 
| **데이터 무결성** | 동일 유저가 동일 워크스페이스에 중복 가입 불가. | WorkspaceMember (복합 PK) | 
| **확장성** | 티켓의 진행 상태(TicketStatus)는 DB 테이블로 관리하여 향후 상태 추가 시 코드 수정 없이 대응 가능해야 함. | TicketStatus | 
| **성능** | 워크스페이스별 티켓 조회 시 응답 시간은 500ms 이내여야 함. | Ticket.workspaceId에 대한 인덱스 고려 |
